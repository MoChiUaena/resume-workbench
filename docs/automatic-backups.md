# 自动备份与本机历史

「备份与恢复」现在有三个入口：手动创建 / ZIP 恢复、自动备份、本机历史。升级前的 ZIP 会继续显示为旧版备份，已有文件不会被清理。

## 自动备份

默认关闭。在「自动备份」勾选启用，选择每天或每周，点击「保存自动备份设置」。首次启用会在一分钟内检查；有数据时创建一份基线，之后到期再检查。频率是从上次检查起计算的 24 小时或 7 天，不是固定的凌晨执行时间。

检查比较当前简历、修订、历史版本、引用附件和相关 PDF 的稳定快照。没有变化时跳过重复副本；尚无简历时只记录检查。快照与打包共用排他锁，保证附件和正文一致。检查期间写入可能短暂等待，未确认的保存仍由原来的自动保存流程处理。

应用关闭时不运行，重新启动后补做一次到期检查。窗口不需要保持打开。「立即检查备份」用于手动提前检查，仍跳过重复内容；需要强制创建新的完整 ZIP 时使用原来的手动备份。

检查失败会保留最近成功的副本和指纹，五分钟后重试，页面显示错误码。设置无法读取或写入时暂停自动执行，用户重新保存后恢复；失败时不会误报已经完成。并发检查不会同时打包两份工作区。

所有手动和自动副本保留，不自动删除。它们保存在当前实例的 `data/backups` 中，与原始数据同属本机应用数据；下载到数据卷之外的独立位置，才能在设备或数据卷不可用时恢复。

## 本机历史

按真实备份时间倒序，每页 20 条，显示日期、手动 / 自动 / 旧版、简历与版本 / 图片数量及大小。可以下载，也可以选择后确认恢复为新记录。恢复经过原有完整格式、文件清单、路径和校验检查，现有简历保留。

新副本记录整个 ZIP 的 SHA-256；下载或恢复前核验大小和校验值。旧 ZIP 没有新索引时只读取受大小限制的摘要，恢复时进行完整验证。无法读取摘要的文件会在页面提示，文件仍保留。

## 数据格式与边界

正文与备份继续使用 schema 4，无数据库迁移。新 ZIP 与原有完整恢复格式兼容。

实例内的 `data/backups/<UUID>.json` 记录副本类型、大小、摘要和工作区指纹；`automatic-settings.json` 保存开关、频率、下次检查和结果。这些管理文件通过临时文件原子替换写入，不进入迁移用的 ZIP。

恢复其他实例的备份不会改变目标实例的自动备份开关。普通 ZIP 保留原始信息与相关 PDF，不是脱敏分享包。部署仍只运行一个 app 和一个数据库，不增加任务队列或外部存储；调度和工作区锁只支持单个 app 进程。

## API

- `GET /api/backups?page=0`：本机历史、分页与不可读取摘要数量。
- `GET /api/backups/automatic`：策略、检查结果、是否运行及设置可读状态。
- `PUT /api/backups/automatic`：保存 `{ "enabled": true, "frequency": "daily" }`，frequency 也可为 weekly。
- `POST /api/backups/automatic/check`：检查并按需创建自动副本，关闭状态返回错误。
- `POST /api/backups/{id}/restore`：从本机副本恢复为新记录。

这些接口继续使用本机同源请求保护。测试结果见 [自动备份验收](automatic-backup-verification.md)。
