# 脱敏 PDF 导出

编辑页顶部的「脱敏 PDF」会先保存当前修改，再打开独立预览。默认将姓名改为「候选人」，隐藏电话、邮箱、城市 / 毕业年份、证件照和学校 Logo；英文标签模式使用 Candidate。每项都可独立选择。

「同步处理正文中的相同信息」默认开启，只替换正文、求职方向、模块标题、条目标题和附注中与所选基本信息完全相同的文字。长字符串优先，按字面匹配，不执行正则表达式或递归替换。其他学校、单位、链接，以及不同格式的电话等仍需结合预览检查；这里不提供自动识别全部个人信息的能力。

确认预览后，点击「导出脱敏 PDF」，下载 `resume-workbench-redacted.pdf`。取消窗口会丢弃本次选择；下一次重新使用默认设置。预览和导出使用同一份后端投影及原有字体、模板、分页脚本，四种模板都可使用。

## 原稿与备份

脱敏设置不写入当前简历。正文、版式、图片 UUID、修订和更新时间保持不变，原图也不删除。预览不会新增历史版本；实际导出按固定修订保留「脱敏 PDF 原稿」快照，该快照保存原始文档以便恢复，生成的 PDF 使用临时脱敏文档。

完整备份继续包含原始正文、原图、历史版本和相关 PDF，它用于迁移整个工作区，不能作为脱敏分享包。恢复备份后，原稿仍可继续编辑，脱敏 PDF 的字节和校验值保持一致。

文档和备份仍为 schema 4，无数据库迁移，也没有导出设置的永久配置。旧 schema 2/3 数据继续兼容读取；旧版普通 PDF 导出的请求格式保持兼容。

## 预览确认与失败处理

打开窗口时固定已保存的修订。选项改变后，导出按钮等待最新预览完成；过期响应和旧 iframe 消息不能启用按钮。最终请求带原稿修订和预览摘要，服务端再次检查修订与投影摘要，变化时拒绝导出，不生成错误的 PDF。

另一页面更新原稿时，窗口提供「关闭并重新载入」，检查新的内容后再导出。PDF 已生成但下载中断时，重试复用同一个文件，不重复生成 PDF 或历史快照。窗口支持 Esc、键盘焦点循环、A/B 界面、深色模式和窄屏。

## API

`POST /api/resumes/{id}/export/preview` 接受以下数据：

```json
{
  "expectedRevision": 2,
  "redaction": {
    "name": true,
    "phone": true,
    "email": true,
    "location": true,
    "photo": true,
    "logo": true,
    "matchingText": true
  }
}
```

返回临时预览 `url`、`digest` 和 `revision`。每个选项必须显式提供；隐藏图片会从投影中移除其 UUID，渲染器不会加载该原图。

`POST /api/resumes/{id}/export` 使用相同修订和选项，并附上返回的 `previewDigest`。省略 `redaction` 时保持原有完整导出行为。接口继续使用本机同源请求保护，基础功能没有外部服务或模型调用。
